## 1. 项目概要与范围

本节是**项目概要**：为什么做、做到什么程度、不做什么。逐条可验收的需求在第 2 节。

**一句话**：把滴答清单里「还没做完的任务」搬到岛上，能按清单筛、按日期看、点一下就完成、顺手就能加一条。

明确要做：

- 任务列表：跨全部任务清单（含收集箱），显示未完成任务。
- 清单筛选：按滴答的清单分组与过滤。
- 时间语义：今天 / 逾期 / 未来，按用户本地日期。
- 日历：月历 + 某一天的任务，附逾期 / 今天 / 无日期的数量。
- 快速添加：待办页底部与日历右栏底部直接输入，回车即建任务，落到当前清单或收集箱。
- 完成回写：勾选直接调滴答接口。
- 品牌呈现：入口与页内用滴答清单自己的标识。

明确不做（不要因为「顺手」加回来）：

- 不做任务编辑：改标题、改到期日、改优先级、删除、移动清单都不在范围内（只做「新建」和「完成」两种写操作）。
- 不做清单管理：不建清单、不改名、不排序。
- 不做 AI Agent 会话展示（那是宿主 Agent 页的事）。
- 不做额度 / 配额环（2026-11-17 已删除，`ddaf09b8`）。
- 不做系统通知推送（已移除 notifications 声明）。
- 不在客户端内跑 MCP：直接用滴答 Open API，MCP 是给 AI 宿主用的。
- 不做完整 RRULE 展开（只处理「锚点在过去的重复任务归今天」）。
- 不修改应用主体的待办功能来替换它，插件与内置待办并存。

## 3. 需求详规（规则、边界、验收、落点）

每条给出：规则 → 边界情况 → 验收方法 → 当前实现位置。实现位置会随适配层变化，规则不会。

### R01 任务范围

- **规则**：遍历滴答的「任务清单」（`kind = TASK`），跳过笔记清单（`NOTE`）；每个清单取全部任务，跳过：笔记类任务（`kind = note`）、无标题。`status ≠ 0` 的任务**不再丢弃**，而是进 R19 的已完成分组（列表接口正常不返回它们，真返回时也不能凭空消失）。**收集箱要算进来**：项目列表通常不含收集箱，需要补一个 `id = inbox` 的伪项目去拉取，否则「全部」里会丢任务。
- **边界**：单个清单请求失败不中断整轮，跳过该清单；全部清单都失败时本轮发布为空。
- **验收**：建 3 个任务清单 + 1 个笔记清单，笔记清单及其任务都不出现；收集箱里放 1 条能看到；在滴答里勾掉一条，下一轮它进「已完成」分组而不是消失。
- **落点**：`plugins/dida365/src/main.rs` / `fetch_projects`、`fetch_project_tasks`、`poll_ticktick`（补 inbox 在 `poll_ticktick` 开头）。

### R02 清单归属与筛选

- **规则**：每行的 `cwd` 存清单名（清单名为空时回落 `TickTick`）；工具栏右侧有一个**清单筛选按钮**，按钮上写当前清单名 + 该清单**未完成数**（未筛选时是「全部」+ 未完成总数），点开是一个菜单：「全部」+ 出现过的清单名，按当前语言排序（顺序稳定，不随数量变动），每项后面跟该清单未完成数，当前项打勾；**只有 1 个清单时不显示这个按钮**；选中后只留该清单的行、菜单自动关闭，行内排序规则不变（见 R05）。
- **计数口径**：计数按该插件块发布的全部会话算（已完成行不计入），**不随当前筛选变化**；菜单里各清单的数字保持不变，方便比较哪儿还有活。
- **行内清单名**：筛选「全部」且不止一个清单时，行详情写「清单 · 到期」；选中某个清单后按钮已经说明范围，行详情只写到期，不再重复清单名（见 R07）。
- **边界**：筛选状态只存在组件内存，重开插件页回到「全部」（**这是有意为之，不是缺陷**；要持久化属于新需求，需先改本文）；日历视图不显示这个按钮，但沿用同一份筛选结果。
- **验收**：3 个清单时按钮显示「全部 + 总数」；点开菜单有 4 项且当前项打勾；各清单数字等于该清单未完成行数；选「计划」后按钮变成「计划 + 数字」、只剩该清单的行、行详情不再带清单名，再打开菜单时各数字不变；只保留 1 个清单时按钮消失。
- **落点**：`src/features/plugins/PluginTasksPanel.tsx` / `PluginBlock`（`lists`、`openCounts`、`openTotal`、`activeList`、`showList`）；`src/features/plugins/PluginListFilter.tsx`（按钮、菜单与关闭逻辑）。

### R03 本地日期语义

- **规则**：滴答的 `dueDate` 是**带时区的时间点**（如 `2026-11-08T16:00:00.000+0000`，配合 `timeZone: Asia/Shanghai`，本地实际是 11-09）。必须解析成带时区时间再换算成本机日期，**禁止截取字符串前 10 位**。`dueDate` 缺失时退回 `startDate`；两者都无 → 视为「未来」组（不显示日期）。
- **边界**：纯日期写法 `YYYY-MM-DD` 直接按当地日期；秒 / 毫秒混用的时间字段统一为 Unix 毫秒。
- **验收**：全天任务 `2026-11-08T16:00:00.000+0000` 在 `Asia/Shanghai` 机器上显示为 11-09 到期，日历落在 9 号。
- **落点**：`main.rs` / `parse_local_due_date`、`parse_epoch_millis`；单测 `parse_due_date_maps_same_instant_to_same_local_day`。

### R04 重复任务

- **规则**：`repeatFlag` 为真（兼容 bool / 非 0 数字 / 非空字符串）即视为重复任务。锚点**早于今天**时：归入「今天」组、不算逾期、详情写「重复任务 · 今天」、日历落在今天。锚点**等于或晚于今天**时按锚点日期正常处理，详情写「重复任务 · MM-DD 到期」。
- **边界**：不做 RRULE 展开、不判断 `UNTIL` 是否已结束——超出本插件范围。
- **验收**：每日重复任务锚点在 2 天前 → 出现在「今天」，详情「重复任务 · 今天」，不出现「逾期 2 天」；日历在今天的格子里。
- **落点**：`main.rs` / `parse_repeat_flag`、`task_bucket_for_due`、`due_detail`、`calendar_due`；单测 `repeated_past_due_task_is_treated_as_today`、`task_rows_carry_the_calendar_day_and_repeat_anchors_move_to_today`。

### R05 默认「到期日」的比较序列（**已达成，2026-11-17；2026-11-18 改为展示层显式比较**）

- **规则**：默认模式（到期日）按以下序列比较未完成行：
  1. **逾期组恒置顶**：`due < 今天` 且 `!repeat`，**按日期算，不看 `status`**；组内再按下面的到期日 / 修改时间比较。
  2. 其余任务按 `due` 升序，**无到期日的排在有日期的之后**。
  3. 同一到期日按 `updatedAt` 降序（最近修改在前）。
  4. `kind !== "task"` 的 Agent 行排在所有任务行之后，Agent 行内部同样按所选模式比较。
- **实现**：`src/features/plugins/pluginSort.ts` 的 `rankOf` + `sortOpenSessions`（`PluginTasksPanel.tsx` 的 `openRows` 调用）；旧实现的 `STATUS_RANK` / `sortedSessions` 已删除，不再用 `waiting / running` 状态分组。
- **注意**：SDK 发布前会按 `updatedAt` 降序重排（`plugins/sdk/src/lib.rs:43`），插件侧排序在网络层一定被覆盖；**验收只看展示层**，不要拿插件侧排序当依据。
- **验收**：造 3 条任务（昨天逾期、今天到期、3 天后到期），顺序必须是这三者的先后；随后改其中一条的修改时间，跨日的顺序不变（只有同一天内部会变）。默认进入插件页时，顺序与 R20 加入前逐行一致。
- **落点**：`pluginSort.ts` 的 `sortOpenSessions`（`due` 分支）。

### R06 勾选完成

- **规则**：每行左侧方形勾选框（复用内置待办的行样式）；点击调宿主 `run_plugin_action`，插件的 action 名固定为 `complete.<projectId>.<taskId>`；插件收到后 `POST /open/v1/project/{pid}/task/{tid}/complete`，然后用内存里的行直接重新 `publish`（不为一次勾选全量拉取）：该行从待办列表移到「已完成」分组（见 R19），不是凭空消失。
- **边界**：该行没有 action 的，勾选框禁用；请求期间禁用按钮，不重复提交（重复完成在滴答侧是幂等的，但别制造多余请求）。
- **验收（已达成）**：正常网络下勾选后 ≤3 秒该行移到「已完成」分组（动作后插件用内存快照立即重发，不再全量拉取）；token 错误或断网时行内显示插件给出的一行错误文案（如 `TickTick completion failed with status 401`，`role="alert"`），勾选按钮在请求期间禁用。
- **落点**：`main.rs` / `complete_task`；`PluginTasksPanel.tsx` / `TaskRow`；`PluginCalendar.tsx` 的当日行。

### R07 行详情

- **规则**（固定文案体系）：无到期 → 不显示详情；今天 → 「今天到期」；逾期 → 「逾期 N 天」；未来 → 「MM-DD 到期」；重复 → 「重复任务 · 今天」/「重复任务 · MM-DD 到期」。筛选「全部」且不止一个清单时行内展示为「清单 · 详情」，即 `cwd` 与 `detail` 用 ` · ` 连接；选中某个清单后只写详情（清单名已由筛选按钮给出，见 R02）。
- **边界**：任务行的详情**不写** Agent 的「进行中 / 待处理」状态词；Agent 会话行才写「状态 · 详情 · 目录」。
- **验收（语言见 R11）**：四种日期状态各造一条，详情文案逐字匹配。
- **落点**：`PluginTasksPanel.tsx` / `dueDetail`、`rowDetail`；`src/i18n/sections/plugins.ts` 的到期文案键（文案归前端，插件只发 `due` 与 `repeat`）。

### R08 日历视图

- **规则**：月历 7 列、可翻月、可回今天；点击日期即选中并显示当天任务，右栏摘要写「N 条待办」（**只算未完成**，不写完成进度）；当天任务行可直接勾选（同 R06）；今天完成的行留在当天、划线显示但不再计数；**逾期任务留在原日期**（用来暴露拖欠），**重复任务归今天**；无 `due` 的行不进日历（只在待办视图出现），改由 R18 的数量与图例交代。
- **边界**：跨月的格子显示为浅色但仍可点；切换日期不改变月份以外的东西。
- **验收**：造 5 条任务分布在 3 个日期，日历圆点数与右栏列表一致；点 15 号只显示 15 号的任务。
- **落点**：`src/features/plugins/PluginCalendar.tsx`；复用 `src/features/todos/` 的 `getMonthGrid`、`TodoDayDetail`、`TodoDayRow`。

### R09 视图切换

- **规则**：「待办 / 日历」分段控件与插件标识放在同一行；默认「待办」；切换时保留当前清单筛选；页高固定 420 px（不超过面板上限），超出滚动。
- **验收**：切到日历、选一个日期、再切回待办，仍停在原来选中的清单。
- **落点**：`PluginTasksPanel.tsx` / `PluginBlock`（复用 `src/features/todos/TodoViewSwitch`，`views = [today, calendar]`）。

### R10 三种状态要能区分（2026-11-18 关闭）

- **规则**：① 没填 token → 引导「去设置里填 API 口令」；② 已配置但没有未完成任务 → 「没有待办」；③ 刷新失败 → 保留上一次的数据，并给出一次失败提示。**不得把「失败」显示成「没有任务」**。
- **现状（修复前）**：三条路都落到同一个空态文案「启用的插件还没有发布任务」。更糟的是失败时 SDK 会 `publish(empty())`（`plugins/sdk/src/lib.rs`），把已有列表清空。
- **落实（分两步，第二步依赖宿主改动）**：
  1. ~~插件内缓存上一次成功结果~~（已改为 **SDK 统一缓存**，所有插件受益）：SDK `run` 缓存最近一次成功的 poll 结果，`poll` 失败时发布 `{...缓存, stale: true}` 而不是 `empty()`；协议 `Contributions` 加 `stale` 布尔（`#[serde(default)]`，旧插件不填不影响宿主解析；反向注意——旧宿主会拒绝带 `stale` 的 publish，插件与宿主需同版本分发）。
  2. ~~宿主暴露 `settingsConfigured` 布尔~~：已落地——宿主 `Live` 加 `settings_configured`（camelCase `settingsConfigured`，`start` 时判定所有 secret 设置非空，无 secret 的插件恒为 true），随 `snapshot` 给前端；前端据 `settingsConfigured === false` 显示「未配置」引导，`stale` 显示一次失败提示并保留行，`composer` 插件无未完成任务显示「没有待办」。

### R19 勾选完成后不消失，进「已完成 N」分组并可撤销（2026-11-18）

- **规则**：「待办」视图分成上下两段——未完成的按 R05 排序；底部是「已完成 N」分组，**只放今天完成的**，组内**最近完成的在上**。已完成的勾选框仍是方形勾（打勾态），点它**撤销完成**并立即把该行放回未完成列表。分组在快速添加输入框之上。

- **撤销**：action 名为 `reopen.<projectId>.<taskId>`；插件 `POST /open/v1/task/{taskId}`，body `{"id": "<taskId>", "projectId": "<pid>", "status": 0}`（**必须带 `projectId`**，否则 404 `task not found`）；成功后立即重新 `publish`。
- **怎么知道任务完成了**：`GET /open/v1/project/{id}/data` 永远只返回未完成任务，**没有**「读已完成任务」的接口（详见附录 A）。所以插件记住上一轮发布过的任务 id，本轮消失的那些逐条 `GET /open/v1/project/{pid}/task/{tid}` 复核：`status ≠ 0` 才算完成，取真实 `completedTime`；`404` / `410` 表示任务已被删除或移走，直接忘记这一行（不再复查）；网络或解析失败保留重试，连续 3 轮失败后放弃；`status = 0` 也先保留重试几轮（列表与单条接口可能短暂不一致），稳定为 0 后才不再复查；不是今天完成的，不进分组。单轮最多复核 20 条，避免批量删除把请求打成突发。
- **已知代价**（可接受）：插件没运行期间、或在别的设备上完成的任务，不会出现在分组里（没有 id 可复核）；撤销后滴答会残留旧的 `completedTime` 字段，判断完成状态**只看 `status`**，不看这个字段。动作成功后立即刷新：完成与撤销直接用内存里的行构造快照（不再为一次点击全量拉取），内存里没有这一行时才回到全量刷新；刷新失败时重发上一次快照并带 `stale`，界面上会显示「刷新失败，显示的是上次的数据」，不会静默停在用户刚点过的那一行（`0.1.9`）。
- **边界**：已完成行占用的额度从 200 条上限里扣（未完成任务优先，见 R14）；分组最多 50 条，跨到第二天自动清空；同一任务在别处被重新打开时，本轮就从分组里移除，不会两处都显示。
- **验收**：勾一条 → 行移到「已完成 1」，未完成列表少一条，进度分母不变；再点这条的勾 → 回到原位、分组消失；断网或 token 错误时点勾，行内显示宿主错误原文且行不动。

### R20 排序方式可切换（2026-11-18）

- **规则**：「待办」视图工具栏的 `.plugin-tasks__aside` 里、进度条左侧有一个排序按钮：`ArrowUpDown` 图标 + **当前规则名**（`到期日` / `最近改动` / `按清单` / `优先级`），`aria-label` 是「排序方式: 规则名」。点开是菜单，**每项两行**——规则名 + 一句说明它怎么改顺序（`到期日`「逾期的在前，没日期的在最后」/ `最近改动`「刚改过的在前」/ `按清单`「同一清单挨在一起，组内按到期日」/ `优先级`「重要的在前，组内按到期日」），当前项打勾。只在**待办视图且存在未完成任务行**时出现，日历视图与空列表不显示。默认 `due`。
- **四种模式**（只作用于未完成行；下面的等级分组在每种模式下都成立，组内再套模式）：
  - `due`（到期日）：`due` 升序（空最后），同日 `updatedAt` 降序。
  - `updated`（最近改动）：`updatedAt` 降序，无到期日的任务仍排在有日期的之后。
  - `list`（按清单）：清单名升序（当前语言），同一清单内 `due` 升序；无到期日的任务仍最后。
  - `priority`（优先级）：高 → 中 → 低 → 无，同一档内 `due` 升序；「无」仍然排在有优先级的之后。
- **为什么是这四种**：旧的 `smart` 与 `due` 共用「逾期 → 有日期 → 无日期 → Agent」等级，只在**同一到期日内部**不同（最近改动 vs 标题），实际输出几乎一样，等于给同一行为起了两个名字——这正是「智能 / 按到期日」读不懂的根因。现在合成一个 `due`，同日一律按最近改动；旧 `due` 的标题序取消。优先级排序（R22）是用户可选的第四项，默认顺序不因它改变。
- **选项按当前范围裁剪**：「按清单」只在**视图里有 ≥ 2 个清单**时出现；筛到单个清单（或插件本来只有一个清单）时它一行也重排不了，就不出现在菜单里，已选中的 `list` 回落成 `due`（`sortModesFor()` + `activeSort`）。
- **不变量**：逾期组在**每种**模式下都置顶（换模式不会把逾期任务藏下去）；已完成行固定在底部按 `updatedAt` 降序（R19 不动）；Agent 行排在任务行之后；不按创建时间或具体时刻排序。
- **交互**：菜单用 `position: fixed` 弹出并夹在视口内（`.plugin-tasks` 是 `overflow-y: auto`，`absolute` 会被裁）；关闭逻辑复刻 `TodoDatePicker`——外部 `pointerdown` / `focusin`、岛折叠、窗口失焦、`Escape`（焦点回到按钮），打开期间调用 `holdIslandPicker()` 防止岛被自动收起。
- **边界**：排序状态只放 `PluginBlock` 的 `useState`，不写 `localStorage`，切视图或重开插件页回到 `due`；排序只重排当前筛选后的可见行，不改变筛选结果；窄窗口下按钮文字省略（`max-width: 92px` + 省略号），不会挤掉进度条。
- **验收**：按钮上读得到当前规则名（含 `aria-label`）；菜单四项（筛到单清单时三项）、每项带一句说明；依次切到「最近改动 / 按清单 / 优先级 / 到期日」，顺序按上述规则变化，切回到期日与默认顺序逐行一致；菜单不被列表滚动裁掉；日历视图没有排序按钮。
- **落点**：`src/features/plugins/pluginSort.ts`（`PluginSortMode` / `PLUGIN_SORT_MODES` / `sortModesFor` / 比较器）、`pluginPriority.ts`（优先级档位与排序权重，R22）、`PluginSortMenu.tsx`（按钮含规则名 + 两行菜单）、`PluginTasksPanel.tsx` 的 `sort` / `sortModes` / `activeSort` / `openRows`、`PluginTasksPanel.css` 的 `.plugin-tasks__sort*` / `.plugin-sort-menu*`、`src/i18n/sections/plugins.ts` 的 `sortMode` / `sortModes`（`{ label, hint }`）、`tests/unit/plugin-sort.test.mjs`。

### R21 待办行可以「开始」，折叠岛显示正在做的事（2026-11-18）

- **规则**：插件页「待办」视图里，每条**未完成**行的右侧有一个「开始」按钮（已完成行没有），旁边是选时长的怀表。「开始」只标记正在做：这一条成为唯一焦点，岛随即收起，折叠岛的待办位显示这条任务的标题；再点同一条停止，点另一条就切过去。用怀表里的小时间开始一轮时，标题旁多一个倒计时，到时显示「时间到」。表现与内置待办的「开始 / 怀表」一致，但插件行不显示按钮文字，只留图标以适配窄页。
- **只在这台机器上**：焦点的开始、停止和每个任务的时长只写 `localStorage`（`fly-island-plugin-focus`），**不调用任何插件 action**，不改滴答里的到期日、标签或状态；换设备看不到，重启后任务仍在快照里就继续显示。
- **自动停止**：这条任务完成后（快照里 `status: "completed"`）、被删除（从快照消失）、插件被停用或卸载时，焦点自动清除，折叠岛回到原来的内容。插件还没发布快照、或最近一次刷新失败（`stale`）时不猜，保留上次的标题，避免网络抖动把正在做的事清掉。
- **不牵连 Agent**：焦点只借用折叠岛的「待办」位，不产生 Agent 会话、不点亮 Agent 状态灯、不进入 Agent 页；任务再多也不会自动显示其中任何一条（R15 不变）。
- **不叠加**：同一时间岛上只显示插件焦点或内置待办的倒计时之一。有插件焦点时，内置待办的计时与轮播不占这一行，避免插件标题配着内置倒计时（或轮播标题盖掉焦点）这种混搭；焦点本身直接占住折叠岛的待办位，不会被运行中的 Agent 会话或歌词按展示优先级挤掉。
- **怀表常驻**：正在做的那一行也保留怀表，否则点过「开始」就再没有给这条任务开计时的入口；只有已完成的行没有开始按钮与怀表。
- **验收**：点「开始」→ 岛收起并显示该标题；点另一条 → 岛切到另一条；再点 → 回到原来的折叠显示。用怀表开始 15 分钟 → 标题旁出现倒计时，到时显示「时间到」；开始时已有运行中的 Agent 会话，岛仍显示这条任务。在滴答里完成/删除这条，或停用插件 → 岛不再显示它。开始前后滴答里的任务数据不变。
- **落点**：`src/features/plugins/pluginFocus.ts`（焦点与时长模型、`resolvePluginFocus` 判定 active/gone/unknown）、`usePluginFocus.ts`（持久化、倒计时到时、消失清理）、`PluginFocusContext.tsx`（插件页与岛共用一份焦点）、`PluginFocusButton.tsx`（开始 / 停止 / 常驻怀表）、`src/lib/islandCollapseRequest.ts`（请求岛收起，避免 feature 直接依赖 `windows/`）、`useCollapsedTodo.ts` 与 `IslandCollapsedBar.tsx`（折叠岛显示标题与倒计时、焦点占住待办位）、`PluginTasksPanel.tsx` 的行接入、`usePlugins.ts` 的 `pluginsLoaded()`（快照到达前不误判任务已消失）。

### R22 任务行显示优先级（2026-11-18）

- **规则**：滴答任务的优先级是四档——`0` 无、`1` 低、`3` 中、`5` 高。插件把原值发进会话的 `priority` 字段，宿主只接受 `0..5`；插件页把它画成标题前的**一个短词**：「高」「中」「低」（英文 High / Med / Low），`0` 不画任何东西。标记是标题行里的内联小块，不占第二行、不把行撑高，`aria-label` 是「标题 · 优先级档位」。
- **默认顺序不动**：`priority` 只是多出来的一列数据，默认 `due` 排序仍按 R05 / R20 的比较序列；想按重要性排时，用户自己在排序菜单里选「优先级」（R20 的第四项）。同一天内没有其他排序差异。
- **数据不写回**：只读滴答的 `priority`，不因显示或排序改任务；`4` 之类不在四档里的值一律当「无」，不凭空造档位。
- **边界**：已完成行同样带标记（它仍是同一条任务）；日历视图不显示标记，只按日期落位；同一清单筛选下标记照常显示。
- **验收**：一条高优先级、一条中、一条低、一条无优先级的任务行，前三条标题前分别有「高 / 中 / 低」，最后一条什么都没有；切英文后是 High / Med / Low；在排序菜单选「优先级」后高在前、无在后，逾期行仍然置顶；不选时默认顺序与加优先级前逐行一致。
- **落点**：`plugins/dida365/src/main.rs` 的 `parse_priority` / `TaskEntry.priority` / `DoneEntry.priority`、`plugins/sdk/src/lib.rs` 的 `task()`、`src-tauri/src/plugin_host/protocol.rs` 的 `priority` 与 0–5 校验、`src/features/plugins/api.ts` 的 `PluginSession.priority`、`pluginPriority.ts`、`PluginTasksPanel.tsx` 的标题前标记、`PluginTasksPanel.css` 的 `.plugin-tasks__priority*`、i18n `priorities` / `priorityLabel`、`tests/regression/plugin-priority.tsx`。

### R23 日期标签筛选（2026-11-18）

- **规则**：「待办」视图里，快速添加框的正上方有一排横向标签：`全部 | 今天 | 明天 | 未来7天 | 逾期`，默认「全部」；标签单选，选中的那个高亮并带 `aria-pressed`。它与工具栏的清单筛选是**「且」**：先按清单取行，再按日期窗口取行。例如选「年度」清单 +「今天」，只剩年度清单里今天到期的行。
- **窗口口径**：
  - `今天`：按今天的本地日期算；重复任务的过去锚点视为今天（R04），也算进来。
  - `明天`：明天的本地日期。
  - `未来7天`：今天起共 7 个自然日，**含今天**，即 `今天 ≤ 到期日 ≤ 今天 + 6 天`。
  - `逾期`：到期日早于今天且**不是重复任务**；重复任务的过去锚点算今天，不算逾期。
  - `全部`：不加日期条件（无到期日的行、Agent 会话行只在这里出现）。
- **计数与进度**：清单菜单里的未完成计数不随日期标签变化（口径同 R02）；进度条按当前两个筛选后的可见行计算。
- **快速添加**：日期标签不影响目标清单：窗口为空时仍按当前选中的清单添加（不会退回收集箱），日期仍取提交当天或日期选择器的值。
- **边界**：标签状态只存在组件内存，重开插件页回到「全部」；只有发布 `due` 的插件块才显示这一排标签（没有到期日的快捷链接类插件不显示，避免一排永远为空的条件）；日历视图不显示标签，也不应用日期窗口（月历本身就是按日期看，沿用清单筛选即可）；筛选后某块只剩已完成行时，它们仍按 R19 进底部「已完成 N」分组。
- **验收**：造昨天（非重复）、今天、明天、今天+3、今天+6、今天+7 各一条，重复任务锚点在昨天一条，无日期一条：五个标签的行数与上述口径逐条一致；`今天` 与 `逾期` 都不把重复任务算错；选清单 +「今天」两个条件同时满足才留下；清空窗口后添加仍进当前清单。
- **落点**：`src/features/plugins/pluginDateFilter.ts`（`PluginDateFilter` / `PLUGIN_DATE_FILTERS` / `shiftDay` / `matchesDateFilter`）、`PluginDateChips.tsx`（一排标签）、`PluginTasksPanel.tsx` 的 `dateFilter` / `inList` / `visible` / `hasDue`、`PluginTasksPanel.css` 的 `.plugin-tasks__dates` / `.plugin-tasks__date*`、i18n `filterDates` / `dateFilters`、`tests/unit/plugin-date-filter.test.mjs`、`tests/regression/plugin-dates.tsx`。

## 4. 语义规则（与平台无关，重写时必须照搬）

这一节是可移植到任何语言的判定逻辑，推荐配单测固化。

### 4.1 分桶

```
today = 本机今天的日期
due  = 任务的本地到期日（可能为空）
repeat = repeatFlag 为真

if due 为空:        桶 = future
else if due < today: 桶 = repeat ? today : overdue
else if due == today: 桶 = today
else:                桶 = future
```

### 4.2 排序

```
未完成行先分等级（四种模式共用）：
  rank = 0  逾期：due < 今天 且 !repeat（按日期算，不看 status）
       = 1  任务且有到期日
       = 2  任务且无到期日
       = 3  Agent 行（kind !== "task"）
再按 rank 升序；同 rank 内按所选模式，最后统一用 updatedAt 降序兜底：
  due      到期日    due 升序（空最后）
  updated  最近改动  updatedAt 降序
  list     按清单    清单名 localeCompare（当前语言）→ due 升序（空最后）
  priority 优先级    priority 5 → 3 → 1 → 0（其他值当 0）→ due 升序

已完成行（completed）单独固定在底部，组内按 updatedAt 降序（不看到期日）
```

说明：逾期组在四种模式下都排最前；任务行永远在 Agent 行之前，无到期日任务永远在有日期任务之后。默认 `due` 就是原来的「逾期 → 今天 → 未来，同日最近修改在前」。「按清单」在视图里只剩一个清单时不出现在菜单里（重排不了任何行）。

注意：SDK 发布前会按 `updatedAt` 重排（`plugins/sdk/src/lib.rs:43`），插件的排序在网络层会被覆盖；**顺序必须在展示层成立**，也就是插件页的 `openRows` / `sortOpenSessions`，不要把插件侧排序当作验收依据（见 R05、R20）。

### 4.3 详情文案

| 情况 | 中文 | 英文（R11 目标） |
|---|---|---|
| 无到期 | 不显示 | 不显示 |
| 今天到期 | 今天到期 | Today |
| 逾期 N 天 | 逾期 N 天 | Overdue N days |
| 未来 | MM-DD 到期 | Due MM-DD |
| 重复且锚点 ≤ 今天 | 重复任务 · 今天 | Repeats today |
| 重复且锚点 > 今天 | 重复任务 · MM-DD 到期 | Repeats · due MM-DD |

### 4.4 日历落位

```
逾期任务：留在原到期日
重复任务：锚点 <= 今天 → 落在今天；否则落在锚点
其余任务：落在到期日
无到期：不进日历
已完成：沿用其到期日（划线显示），但不计入任何数字；左边方框是勾选态，点它撤销
```

- 日历右栏每一行**左边的方框就是勾选框**：未完成点它 → 完成；已完成点它 → 撤销。右边不再挂勾选按钮。

### 4.5 快速添加动作契约

```
create.<YYYY-MM-DD>.<标题>
create.<YYYY-MM-DD>.list:<清单id>.<标题>
```

- 前两个点是有含义的分隔符，**标题里其余的点原样保留**；`list:` 形式多切一层。
- 日期必须是合法 `YYYY-MM-DD`；标题 trim 后非空。
- 新建一律是全天任务：`dueDate = "<日期>T00:00:00+0000"`、`isAllDay = true`。
- 带 `list:<清单id>` 落到该清单；不带则落到收集箱。
- 成功后插件立即重发快照，让新行当轮出现。
- **长度限制前后端必须同一口径**：200 个字符（前端 `[...title].length`，插件 `chars().count()`）。

### 4.6 完成与撤销动作契约

```
complete.<清单id>.<任务id>   → POST /open/v1/project/{pid}/task/{tid}/complete
reopen.<清单id>.<任务id>     → POST /open/v1/task/{tid}  { id, projectId, status: 0 }
```

- id 里不含点号，按**第一个**点切成清单 id 与任务 id。
- 两条动作成功后都立即重发快照，不用等下一轮轮询。
- 判断「完成」只看 `status ≠ 0`；`completedTime` 在撤销后可能仍是旧值，不能拿它当状态。
- 已完成行靠「上一轮有、这一轮消失」加一次单条 `GET` 复核得出，详见 R19。

## 7. 验收

### 7.1 环境与数据准备

用真实滴答账号，在「计划」清单里造 6 条：

1. 今天到期的一条；
2. 逾期 2 天的一条；
3. 3 天后到期的一条；
4. 每日重复、锚点在 2 天前的一条；
5. 无到期日的一条；
6. 一条已完成的（原本完成，验证不进「已完成」分组：插件只认自己看着变成已完成的行）。

另建一个「笔记」清单放 1 条笔记，收集箱放 1 条任务（分别验证 R01 的两个排除/包含分支）。快速添加那几步会真的建任务，验完自行清理。

## 8. 变更纪律

- **需求变更**：只有你能提。改需求要同时改三处：第 2 节需求表、第 3 节对应详规、第 7 节验收步骤；并在下面登记。
- **适配变更**（换语言、升 apiVersion、改 UI 归属、换分发）：不需要改需求，但必须重跑 7.3 与 7.2 全表。
- **修复已达成项**（如顺手改文案）：视为实现层变更，需保证 7.2 不失守。
- **不允许**为了适配方便删需求。上游不支持某能力时，写「阻塞 + 替代方案」，不要静默降级。

## 附录 A：滴答 Open API 事实（实测，2026-11-16 首测，2026-11-18 补测完成 / 撤销路径）

| 项 | 结论 |
|---|---|
| 认证 | 个人 API 口令，`Authorization: Bearer <token>`；网页版「设置 → 账户与安全 → API 口令」获取；无需 OAuth |
| 端点 1 | `GET /open/v1/project` — 清单列表，`kind` 区分 TASK / NOTE |
| 端点 2 | `GET /open/v1/project/{id}/data` — `{ project, tasks, columns }` |
| 端点 3 | `POST /open/v1/project/{projectId}/task/{taskId}/complete` — 完成写操作 |
| 端点 4 | `POST /open/v1/task` — 新建任务；body `{title, dueDate: "<日期>T00:00:00+0000", isAllDay, projectId?}`，不带 `projectId` 进收集箱 |
| 端点 5 | `POST /open/v1/task/{tid}` — 通用更新，**撤销完成**用它：body `{id, projectId, status: 0}`，缺 `projectId` 返回 404 `task not found`（实测 200，任务回到 `/data`） |
| 端点 6 | `GET /open/v1/project/{pid}/task/{tid}` — 单条任务，**能读到已完成**（`status: 2` + 真实 `completedTime`），是唯一可靠来源 |
| 已完成批量端点 | **不存在**：`GET /project/{id}/task/completed` → 404 `task not found: completed`（路由把它当 taskId）、POST → 405；`/project/{id}/completed`、`/completedTask`、`/task/completedByDay`、`/completed/list` 全 404；`/open/v2/...` → 403；`/data` 加 `status=2` / `completed=true` / `includeCompleted=true` / `from&to` 参数被忽略，始终只回 `status 0` |
| 全局读端点 | 不存在：`GET /open/v1/task` 返回 405，只能 1 + N 次 fan-out；收集箱数据走 `GET /open/v1/project/inbox/data` |
| 规模与限流 | 5 个清单一轮 4 次请求、约 300 ms；限流宽松（约 100 次/分钟），3 分钟轮询余量约 20 倍 |
| 字段 | 实测并集 24 个；实现用 `id`、`title`、`dueDate`、`startDate`、`modifiedTime`、`createdTime`、`status`、`kind`、`repeatFlag`、`priority` |
| 取值 | `priority ∈ 0/1/3/5`（无 / 低 / 中 / 高）；`status 0 = 未完成`；日期 `yyyy-MM-dd'T'HH:mm:ssZ`（`+0000` 无冒号） |
| 已知坑 | dueDate 是 UTC 时间点；重复任务 dueDate 是锚点；**列表读不到已完成任务**（`/data` 只回 `status 0`，只能靠单条 GET 复核）；撤销完成后 `completedTime` 残留旧值，判断完成只看 `status`；`dida365` 的 token 打到国际版 `api.ticktick.com` 会 401 `invalid_token`（两站账号不通用） |
